# Rate Limiting Bypass - CodeShack.io Password Reset

## Summary

I identified a Rate Limiting Bypass vulnerability in the CodeShack.io password reset functionality.

The application restricts the number of password reset attempts per email address, but the restriction is not enforced properly. By using a brute-force attack with different payloads (e.g., numeric, alphabetical, or special character variations), an attacker can bypass the rate limit and send multiple password reset requests to the same email address.

This vulnerability allows an attacker to flood a target user's email inbox with password reset requests, potentially leading to denial of service (DoS), user frustration, or social engineering attacks.

## Vulnerability Type

**Rate Limiting Bypass / Brute Force (Intruder Attack)**

## Vulnerable Parameter

```text
email
```

## Vulnerable URL

```text
https://koko-codeshackio.kzlabs.in/verify-otp.php
```

## Steps to Reproduce

1. Navigate to the vulnerable CodeShack.io password reset page.

2. Enter a target email address in the password reset form.

3. Intercept the request using Burp Suite, OWASP ZAP, or a similar proxy tool.

4. Send the request to Intruder (Burp Suite) or similar brute-force tool.

5. Configure the attack with various payloads (numeric, alphabetical, or special characters) to bypass rate limiting.

6. Launch the attack.

7. Observe that all requests return a `302 Found` response with the `Location: verify-otp.php` header.

8. The target email address receives multiple password reset emails.

## Payloads Used

```text
Numeric: 0-9
Alphabetical: a-z, A-Z
Special Characters: !@#$%^&*()
Combinations: payload+number, payload+random
```

## Proof of Concept

The application sends a password reset request to the server:

```http
POST /verify-otp.php HTTP/2
Host: koko-codeshackio.kzlabs.in
Content-Type: application/x-www-form-urlencoded

email=target@example.com
```

The server responds with a redirect:

```http
HTTP/1.1 302 Found
Content-Type: text/html; charset=UTF-8
Location: verify-otp.php
Server: cloudflare
X-Powered-By: PHP/8.2.33
Cache-Control: no-store, no-cache, must-revalidate
```

The rate limit can be bypassed by:

1. Using different payload values (numeric, alphabetical, special characters)
2. Adding random parameters or headers
3. Using different IP addresses or User-Agent strings
4. Manipulating the request body or headers

All requests receive a `302 Found` response, indicating that the rate limit does not effectively block multiple requests.

## Impact

This Rate Limiting Bypass vulnerability allows an attacker to:

- Flood a target user's inbox with password reset requests
- Perform denial of service (DoS) attacks on specific email addresses
- Overwhelm the application's email sending capabilities
- Create user frustration and confusion
- Potentially conduct social engineering attacks
- Bypass anti-brute-force protections

## Recommendation

To mitigate this vulnerability:

- **Server-Side Rate Limiting**: Implement rate limiting on the server side using a database or cache.
  ```php
  $email = $_POST['email'];
  $ip = $_SERVER['REMOTE_ADDR'];
  $key = "rate_limit:$email:$ip";
  $attempts = redis_get($key);
  if ($attempts > 5) {
      return "Too many attempts. Please try again later.";
  }
  redis_incr($key, 3600); // Increment and expire after 1 hour
  ```

- **CAPTCHA Implementation**: Implement CAPTCHA (reCAPTCHA, hCaptcha) after a certain number of attempts.

- **IP-Based Throttling**: Implement rate limiting based on IP address in addition to email.

- **User-Agent Validation**: Track and limit requests based on User-Agent strings.

- **Email Verification**: Implement additional verification steps (e.g., link expiration, one-time tokens).

- **Time Delays**: Implement exponential backoff between attempts.

- **Logging and Monitoring**: Log all reset requests and monitor for anomalies.

- **Regular Security Audits**: Conduct regular assessments to identify and fix vulnerabilities.
