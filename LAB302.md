# Open Redirect - Blog URL Path Manipulation

## Summary

I identified an Open Redirect vulnerability in the application's blog URL handling functionality.

The application accepts a user-controlled URL through the blog path and uses it to perform a redirect without proper validation of the destination URL. By manipulating the blog URL path with `///bing.com/`, an attacker can redirect victims to arbitrary malicious websites while maintaining the appearance of legitimacy through the trusted domain.

An attacker can craft a malicious URL using the vulnerable `kzlabs.in/302.php` domain and trick a victim into clicking it. Once the victim clicks the link, they are redirected to the attacker-controlled website (in this case, `bing.com`), which can be used for phishing attacks, credential theft, or malware distribution.

## Vulnerability Type

**Open Redirect**

## Vulnerable Parameter

```text
blog_url (path-based parameter)
```

## Vulnerable URL

```text
https://kzlabs.in/302.php///bing.com/?category=developers
```

## Steps to Reproduce

1. Open the vulnerable page.

2. Manipulate the blog URL path with an external domain:

   ```text
   ///bing.com/
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/302.php///bing.com/?category=developers
   ```

4. Observe that the application redirects or attempts to redirect to the supplied external domain.

## Payload Used

```text
///bing.com/
```

URL-encoded version:
```text
%2F%2F%2Fbing.com%2F
```

Alternative payloads:
```text
//evil.com
//attacker.com/phishing
//malware-site.com
```

## Proof of Concept

The application accepts the value from the blog URL path and uses it to perform a redirect without validating the destination URL.

The payload works by:
1. The application reads the blog URL path parameter from the URL
2. The value is used in a redirect without proper validation
3. The user is redirected to the attacker-controlled domain
4. The `///bing.com/` pattern bypasses simple URL validation checks

```http
GET /302.php///bing.com/?category=developers HTTP/1.1
Host: kzlabs.in

HTTP/1.1 302 Found
Location: https://bing.com/
```

The user is silently redirected to the external site, potentially without any visual indication.

## Impact

Open Redirect vulnerabilities can be used for:

- **Phishing Attacks**: Victims are redirected to fake login pages that steal credentials
- **Malware Distribution**: Redirect users to sites hosting malware
- **Bypassing Security Controls**: Redirects can bypass email filters or security checks
- **Session Fixation**: Can be combined with other attacks for session hijacking
- **Trust Abuse**: Links appear to come from a trusted domain

An attacker can:

- Create convincing phishing links using the trusted domain
- Steal user credentials via fake login pages
- Bypass anti-phishing filters that trust the domain
- Distribute malware through trusted redirects

## Recommendation

To mitigate this vulnerability:

- **URL Validation**: Validate the redirect URL against a whitelist of allowed domains.
  ```php
  $allowedDomains = ['omise.co', 'blog.omise.co', 'localhost'];
  $parsedUrl = parse_url($_GET['blog_url']);
  if (!in_array($parsedUrl['host'], $allowedDomains)) {
      // Redirect to default page or error
  }
  ```

- **Relative Paths Only**: Only allow relative paths, not absolute URLs.
  ```php
  if (strpos($_GET['blog_url'], 'http') !== false || strpos($_GET['blog_url'], '//') !== false) {
      // Reject external URLs
  }
  ```

- **Referer Validation**: Validate that the request comes from within the application.

- **Content Security Policy (CSP)**: Implement a CSP that restricts navigation to unauthorized domains.

- **Redirect Confirmation**: Display a warning page before redirecting to external domains.
  ```html
  You are being redirected to: <?php echo htmlspecialchars($redirectUrl); ?>
  Are you sure you want to continue?
  ```

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block open redirect payloads.

- **Security Headers**: Implement security headers for additional protection.

- **Regular Security Audits**: Conduct regular assessments and code reviews to identify vulnerabilities.
