# XML External Entity (XXE) Injection - Employee Directory

## Summary

I identified an XML External Entity (XXE) Injection vulnerability in the employee directory search functionality of the GlobalTech application.

The application accepts user-controlled XML input through a POST request to search for employees. The XML parser is configured to process external entity definitions without proper restrictions, allowing an attacker to read arbitrary files from the server. By defining an external entity that references a local file, an attacker can cause the application to include the file's contents in the response.

An attacker can craft a malicious XML payload that reads sensitive files from the server, potentially leading to information disclosure, credential theft, or further exploitation.

## Vulnerability Type

**XML External Entity (XXE) Injection**

## Vulnerable Parameter

```text
XML body (name element)
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/xml/index.php
```

## Steps to Reproduce

1. Navigate to the vulnerable employee directory at `https://kzlabs.in/subdomains/xml/index.php`.

2. Intercept the search request using Burp Suite or a similar proxy tool.

3. Replace the XML body with the following XXE payload:

   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
   <search>
     <name>&xxe;</name>
     <department></department>
   </search>
   ```

4. Send the request.

5. Observe that the response contains the contents of `/etc/passwd` embedded in the JSON `query.name` field.

## Payload Used

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<search>
  <name>&xxe;</name>
```

## Impact

An attacker can:

- Read arbitrary files from the server (`/etc/passwd`, `/etc/shadow`, application config files)
- Extract sensitive credentials (database passwords, API keys)
- Perform Server-Side Request Forgery (SSRF) to access internal services
- Perform denial of service (billion laughs attack)
- Potentially achieve Remote Code Execution (RCE) via PHP filter chains or by reading sensitive files
- Enumerate internal network services
- Bypass authentication by reading session files or configuration

## Recommendation

To mitigate this vulnerability:

- **Disable External Entities**: Configure the XML parser to disable DTDs and external entities.
  ```php
  libxml_disable_entity_loader(true);
  ```

- **Use Safe XML Parsers**: Use parsers that do not process external entities by default.
  ```php
  $doc = new DOMDocument();
  $doc->loadXML($xml, LIBXML_NONET | LIBXML_NOENT);
  ```

- **Use JSON Instead of XML**: If possible, replace XML with JSON for data exchange.

- **Validate XML Input**: Reject any XML containing DOCTYPE declarations or entity definitions.
  ```php
  if (preg_match('/<!DOCTYPE|<!ENTITY/i', $xml)) {
      die("XML not allowed.");
  }
  ```

- **Use `libxml_set_external_entity_loader`**: Set a custom entity loader that returns null.
  ```php
  libxml_set_external_entity_loader(function() { return null; });
  ```

- **Upgrade PHP**: Use PHP 8.0+ where external entity loading is disabled by default.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block XXE payloads.

- **Principle of Least Privilege**: Run the web server with minimal permissions.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
