# Rate Limiting Bypass - OTP Verification Endpoint

## Summary

I identified a Rate Limiting Bypass vulnerability in the OTP verification endpoint at `https://koko-rate.kzlabs.in/users/testqr.php`.

The application processes OTP verification requests without implementing proper rate limiting or request throttling mechanisms. By using a brute-force attack with sequential numeric payloads (e.g., 0123, 1234, 2345, etc.), an attacker can send multiple OTP verification attempts to the server without being blocked or rate-limited. All requests return a `302 Found` status code, redirecting to `../index.php?error=invalid_code`, confirming that the application processes each attempt without enforcing any rate limits.

This vulnerability allows attackers to perform brute-force attacks on OTP codes, potentially leading to account takeover or unauthorized access.

## Vulnerability Type

**Rate Limiting Bypass / OTP Brute Force**

## Vulnerable Parameter

```text
OTP code (numeric payload)
```

## Vulnerable URL

```text
https://koko-rate.kzlabs.in/users/testqr.php
```

## Steps to Reproduce

1. Navigate to the vulnerable OTP verification page.

2. Intercept a request using Burp Suite, OWASP ZAP, or a similar proxy tool.

3. Send the request to Intruder (Burp Suite) or similar brute-force tool.

4. Configure the attack with sequential numeric payloads (e.g., 0123, 1234, 2345, 3456, 4567, 5678, 6789, 7890, 0987, 9876, 5432).

5. Launch the attack.

6. Observe that all requests return a `302 Found` status code, indicating that rate limiting is not being enforced.

## Payloads Used

```text
0123, 1234, 2345, 3456, 4567, 5678, 6789, 7890, 0987, 9876, 5432
```

## Proof of Concept

The application sends a POST request to the server with an OTP code:

```http
POST /users/testqr.php HTTP/2
Host: koko-rate.kzlabs.in
Cookie: PHPSESSID=a6c919508703fcc0e4ac75a5d2bc70fd
Content-Type: application/x-www-form-urlencoded

otp=0123
```

The server responds with a `302 Found` status code for all requests:

```http
HTTP/2 302 Found
Date: Tue, 25 Aug 2026 16:04:49 GMT
Content-Type: text/html; charset=UTF-8
Location: ../index.php?error=invalid_code
Server: cloudflare
X-Powered-By: PHP/8.2.33
Cache-Control: no-store, no-cache, must-revalidate
```

All 11 requests in the attack returned `302 Found`:

| Request | Payload | Status Code | Length |
|---|---|---|---|
| 4 | 0123 | 302 | 803 |
| 5 | 1234 | 302 | 807 |
| 6 | 2345 | 302 | 795 |
| 7 | 3456 | 302 | 796 |
| 8 | 4567 | 302 | 799 |
| 9 | 5678 | 302 | 805 |
| 10 | 6789 | 302 | 805 |
| 11 | 7890 | 302 | 803 |

This confirms that the rate limiting mechanism is either not implemented or easily bypassed, allowing unlimited OTP attempts.

## Impact

This Rate Limiting Bypass vulnerability allows an attacker to:

- Perform brute-force attacks on OTP codes
- Bypass multi-factor authentication (MFA)
- Gain unauthorized access to user accounts
- Perform account takeover attacks
- Bypass rate limiting and anti-brute-force protections

## Recommendation

To mitigate this vulnerability:

### Server-Side Rate Limiting for OTP
```php
$ip = $_SERVER['REMOTE_ADDR'];
$email = $_POST['email'] ?? '';
$key = "otp_rate_limit:$ip:$email";
$attempts = redis_get($key);
if ($attempts > 5) {
    http_response_code(429);
    return "Too many OTP attempts. Please try again later.";
}
redis_incr($key, 300); // Increment and expire after 5 minutes
```

### OTP Attempt Throttling
```php
$ip = $_SERVER['REMOTE_ADDR'];
$key = "otp_throttle:$ip";
$attempts = redis_get($key);
if ($attempts > 10) {
    http_response_code(429);
    return "Too many OTP attempts from this IP.";
}
redis_incr($key, 300); // Increment and expire after 5 minutes
```

### Account Lockout After Failed Attempts
```php
$email = $_POST['email'] ?? '';
$key = "account_lockout:$email";
$failures = redis_get($key);
if ($failures > 5) {
    return "Account locked. Please contact support.";
}
redis_incr($key, 900); // Increment and expire after 15 minutes
```

### Additional Recommendations

- **OTP Expiration**: Implement short OTP expiration times (e.g., 5-10 minutes).
- **CAPTCHA Implementation**: Implement CAPTCHA after a certain number of failed attempts.
- **Progressive Delays**: Implement increasing delays between OTP attempts.
- **Logging and Monitoring**: Log all OTP attempts and monitor for anomalies.
- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block brute-force attacks.
- **Rate Limiting Headers**: Implement `X-RateLimit-*` headers to inform clients of limits.
- **IP Blacklisting**: Blacklist IPs that exceed the rate limit.
- **Regular Security Audits**: Conduct regular assessments to identify and fix vulnerabilities.
- **Intrusion Detection System (IDS)**: Deploy IDS to detect abnormal traffic patterns.
