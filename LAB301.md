# Open Redirect - LinkDash URL Shortener

## Summary

I identified an Open Redirect vulnerability in the LinkDash URL shortening application.

The application accepts user-controlled input through the `toWww` parameter and uses it to redirect users without proper validation of the destination URL. By supplying an external domain, an attacker can redirect victims to arbitrary malicious websites while maintaining the appearance of legitimacy through the trusted domain.

An attacker can craft a malicious URL using the vulnerable LinkDash domain and trick a victim into clicking it. Once the victim clicks the link, they are silently redirected to the attacker-controlled website, which can be used for phishing attacks, credential theft, or malware distribution.

## Vulnerability Type

**Open Redirect**

## Vulnerable Parameter

```text
toWww
```

## Vulnerable URL

```text
https://kzlabs.in/301.php?toWww=https://evil.com
```

## Steps to Reproduce

1. Open the vulnerable LinkDash page.

2. Replace the value of the `toWww` parameter with an external domain:

   ```text
   https://evil.com
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/301.php?toWww=https://evil.com
   ```

4. Observe that the browser redirects to the supplied external domain.

## Payload Used

```text
https://evil.com
```

URL-encoded version:
```text
https%3A%2F%2Fevil.com
```

Alternative payloads:
```text
//evil.com
https://attacker.com/phishing
http://malware-site.com
```

## Proof of Concept

The application accepts the value of the `toWww` parameter and uses it to perform a redirect without validating the destination URL.

The payload works by:
1. The application reads the `toWww` parameter from the URL
2. The value is used in a redirect without proper validation
3. The browser is redirected to the attacker-controlled domain

```http
GET /301.php?toWww=https://evil.com HTTP/1.1
Host: kzlabs.in

HTTP/1.1 302 Found
Location: https://evil.com
```

The user is silently redirected to the malicious site, potentially without any visual indication.

## Impact

Open Redirect vulnerabilities can be used for:

- **Phishing Attacks**: Victims are redirected to fake login pages that steal credentials
- **Malware Distribution**: Redirect users to sites hosting malware
- **Bypassing Security Controls**: Redirects can bypass email filters or security checks
- **Session Fixation**: Can be combined with other attacks for session hijacking
- **Trust Abuse**: Links appear to come from a trusted domain (LinkDash)

An attacker can:

- Create convincing phishing links using the trusted domain
- Steal user credentials via fake login pages
- Bypass anti-phishing filters that trust the LinkDash domain
- Distribute malware through trusted redirects

## Recommendation

To mitigate this vulnerability:

- **URL Validation**: Validate the redirect URL against a whitelist of allowed domains.
  ```php
  $allowedDomains = ['bing.com', 'google.com', 'example.com'];
  $parsedUrl = parse_url($_GET['toWww']);
  if (!in_array($parsedUrl['host'], $allowedDomains)) {
      // Redirect to default page or error
  }
  ```

- **Relative Paths Only**: Only allow relative paths, not absolute URLs.
  ```php
  if (strpos($_GET['toWww'], 'http') !== false) {
      // Reject external URLs
  }
  ```

- **Referer Validation**: Validate that the request comes from within the application.

- **Content Security Policy (CSP)**: Implement a CSP that restricts navigation to unauthorized domains.

- **Redirect Confirmation**: Display a warning page before redirecting to external domains.
  ```html
  You are being redirected to: <?php echo htmlspecialchars($redirectUrl); ?>
  Are you sure you want to continue?
  ```

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block open redirect payloads.

- **Security Headers**: Implement security headers for additional protection.

- **Regular Security Audits**: Conduct regular assessments and code reviews to identify vulnerabilities.
