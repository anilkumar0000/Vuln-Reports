# SQL Injection - Time-Based Blind

## Summary

I identified a Time-Based Blind SQL Injection vulnerability in the application.

The application accepts user-controlled input and concatenates it directly into SQL queries without proper sanitization or parameterization. By injecting time-based SQL payloads, an attacker can infer database information based on the response time of the server. The payloads cause the database to delay its response, allowing the attacker to determine if the injection was successful.

An attacker can craft malicious inputs that cause the database to sleep for a specified duration, confirming the presence of a SQL injection vulnerability.

## Vulnerability Type

**SQL Injection (Time-Based Blind)**

## Vulnerable Parameter

```text
id (or similar numeric parameter)
```

## Vulnerable URL

```text
https://kzlab.si/sqli.php?id=1
```

## Steps to Reproduce

1. Intercept a request using Burp Suite or similar proxy tool.

2. Replace the parameter value with a time-based payload:

   ```text
   'XOR(if(now()=sysdate(),sleep(5*5),0))OR'
   ```

3. Send the request.

4. Observe that the server takes approximately 25 seconds to respond, confirming successful injection.

## Payloads Used

```text
'XOR(if(now()=sysdate(),sleep(5*5),0))OR'

if(1=1, sleep(10),0)/XOR(if(1=1, sleep(10),0))OR"XOR(if(1=1, sleep(10),0))"
```

## Proof of Concept

The application takes user input and concatenates it into a SQL query:

```sql
SELECT * FROM table WHERE id = '1'XOR(if(now()=sysdate(),sleep(10),0))XOR'Z'
```

When the condition `now()=sysdate()` evaluates to true, the `sleep(10)` function is executed, causing a 10-second delay in the response.

The payload works by:
1. Breaking out of the SQL query context
2. Injecting a conditional sleep statement
3. The database evaluates the condition and delays the response if true
4. The delay confirms the vulnerability exists

## Impact

An attacker can:

- Enumerate database structure and content without seeing output
- Extract sensitive data (usernames, passwords, personal information)
- Bypass authentication mechanisms
- Gain unauthorized access to the application

## Recommendation

To mitigate this vulnerability:

- Use **prepared statements** with parameterized queries.
  ```php
  $stmt = $conn->prepare("SELECT * FROM table WHERE id = ?");
  $stmt->bind_param("i", $id);
  $stmt->execute();
  ```

- Use **input validation** to ensure numeric parameters are actually integers.
  ```php
  $id = (int)$_GET['id'];
  ```

- Use **output encoding** when displaying user-controlled data.
