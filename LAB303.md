# Reflected Cross-Site Scripting (XSS) - Semrush Domain Parameter

## Summary

I identified a Reflected Cross-Site Scripting (XSS) vulnerability in the `domain` parameter of the Semrush SEO tool application.

The application accepts user-controlled input through the `domain` GET parameter and reflects it back to the page without proper sanitization or output encoding. By injecting HTML tags such as `<h1>` with inline styles, an attacker can manipulate the visual appearance of the page and inject arbitrary HTML content.

An attacker can craft a malicious URL and trick a victim into clicking it. Once the victim visits the page, the injected HTML is rendered by the browser within the context of the vulnerable application.

## Vulnerability Type

**Cross-Site Scripting (XSS) - Reflected**

## Vulnerable Parameter

```text
domain
```

## Vulnerable URL

```text
https://kzlabs.in/303.php?domain=<h1 style="color:red">HACKED</h1>
```

## Steps to Reproduce

1. Open the vulnerable page.

2. Replace the value of the `domain` parameter with the following payload:

   ```text
   <h1 style="color:red">HACKED</h1>
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/303.php?domain=%3Ch1%20style%3D%22color%3Ared%22%3EHACKED%3C%2Fh1%3E
   ```

4. Observe that the HTML is rendered by the browser, displaying "HACKED" in red text.

## Payload Used

```text
<h1 style="color:red">HACKED</h1>
```

URL-encoded version:
```text
%3Ch1%20style%3D%22color%3Ared%22%3EHACKED%3C%2Fh1%3E
```

## Proof of Concept

The application accepts the value of the `domain` parameter and reflects it directly into the page HTML without proper sanitization.

The payload works by:
1. Injecting an HTML heading tag (`<h1>`) with an inline style attribute
2. The browser renders the injected HTML within the page

```html
<!-- Injected payload rendered in the page: -->
<h1 style="color:red">HACKED</h1>
```

The injected HTML is reflected in the page content, confirming the vulnerability.

## Impact

Reflected XSS vulnerabilities can be used for:

- **Phishing**: Attackers can inject fake login forms or misleading content
- **Defacement**: Visual manipulation of the webpage
- **Information Disclosure**: Injecting elements that capture user input
- **Social Engineering**: Creating convincing fake messages or alerts
- **Session Hijacking**: Redirecting users to malicious sites

An attacker can:

- Steal session cookies and hijack user accounts
- Perform actions on behalf of the authenticated user
- Deface the webpage or manipulate its content
- Redirect users to malicious websites
- Capture keystrokes or sensitive information

## Recommendation

To mitigate this vulnerability:

- **Output Encoding**: Use `htmlspecialchars()` (or an equivalent output-encoding function) before rendering user-controlled data in HTML.
  ```php
  echo htmlspecialchars($_GET['domain'], ENT_QUOTES, 'UTF-8');
  ```

- **Input Validation**: Validate and sanitize all user inputs. Consider using a whitelist approach to allow only safe characters.
  ```php
  $domain = preg_replace('/[^a-zA-Z0-9\s\-_.]/', '', $_GET['domain']);
  ```

- **Content Security Policy (CSP)**: Implement a strict CSP to restrict inline styles and unauthorized content.

- **Context-Aware Escaping**: Use appropriate escaping based on where the data is placed (HTML body, attributes, JavaScript).

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block malicious XSS payloads.

- **Security Headers**: Implement security headers like `X-XSS-Protection` and `X-Content-Type-Options` for additional protection.

- **Regular Security Audits**: Conduct regular assessments and code reviews to identify vulnerabilities.
