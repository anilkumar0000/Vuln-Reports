# Reflected HTML Injection in Search Functionality

## Summary

I identified a Reflected HTML Injection vulnerability in the search functionality of the ShopZone application.

The application accepts user-controlled input through the `q` GET parameter and reflects it back to the page without proper sanitization or output encoding. By injecting HTML markup, such as `<h1>` tags with inline styles, an attacker can manipulate the visual appearance of the page and inject arbitrary HTML content. This can be used for phishing attacks, defacement, or further exploitation.

An attacker can craft a malicious URL and trick a victim into clicking it. Once the victim visits the page, the injected HTML is rendered by the browser within the context of the vulnerable application.

## Vulnerability Type

**HTML Injection (Reflected)**

## Vulnerable Parameter

```text
q
```

## Vulnerable URL

```text
https://kzlabs.in/1202.php?q='>&<h1 style="color:red">HACKED</h1>
```

## Steps to Reproduce

1. Open the vulnerable page.

2. Replace the value of the `q` parameter with the following payload:

   ```text
   '>&<h1 style="color:red">HACKED</h1>
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/1202.php?q=%27%3E%26%3Ch1%20style%3D%22color%3Ared%22%3EHACKED%3C%2Fh1%3E
   ```

4. Observe that the HTML is rendered by the browser, displaying "HACKED" in red text.

## Payload Used

```text
'>&<h1 style="color:red">HACKED</h1>
```

URL-encoded version:
```text
%27%3E%26%3Ch1%20style%3D%22color%3Ared%22%3EHACKED%3C%2Fh1%3E
```

## Proof of Concept

The application accepts the value of the `q` parameter and reflects it directly into the page HTML without proper sanitization.

The payload works by:
1. Breaking out of the existing HTML context using `'>`
2. Injecting an HTML heading tag (`<h1>`) with an inline style attribute
3. The browser renders the injected HTML within the page

```html
<!-- Injected payload rendered in the page: -->
'>&<h1 style="color:red">HACKED</h1>
```

The injected HTML appears in the search results heading, confirming the vulnerability.

## Impact

HTML Injection vulnerabilities can be used for:

- **Phishing**: Attackers can inject fake login forms or misleading content
- **Defacement**: Visual manipulation of the webpage
- **Information Disclosure**: Injecting elements that capture user input
- **Social Engineering**: Creating convincing fake messages or alerts
- **Session Hijacking**: Redirecting users to malicious sites

## Recommendation

To mitigate this vulnerability:

- **Output Encoding**: Use `htmlspecialchars()` (or an equivalent output-encoding function) before rendering user-controlled data in HTML.
  ```php
  echo htmlspecialchars($_GET['q'], ENT_QUOTES, 'UTF-8');
  ```

- **Input Validation**: Validate and sanitize all user inputs. Consider using a whitelist approach to allow only safe characters.
  ```php
  $query = preg_replace('/[^a-zA-Z0-9\s\-_.]/', '', $_GET['q']);
  ```

- **Content Security Policy (CSP)**: Implement a strict CSP to restrict inline styles and unauthorized content.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block malicious HTML payloads.

- **Security Headers**: Implement security headers like `X-XSS-Protection` and `X-Content-Type-Options` for additional protection.

- **Regular Security Audits**: Conduct regular assessments and code reviews to identify vulnerabilities.
